# Reproducing This Experiment

This folder collects the best AGRS + NIXL P/D-disaggregated Qwen3-MoE run so far.
It contains the raw run logs, AIPerf outputs, CPU/JSONL summaries, timeline plots,
and transfer-volume slowdown figures for:

```text
run_name: e2e_agrs_nixl_cpu_2000req_r20_o1000_2026-06-02T06-55-58Z
request_rate: 20 requests/s
max_completion_tokens: 1000
warmup: 1000 requests
main: 2000 requests
backend: allgather_reducescatter / AgRsAll2AllManager
moe_backend: triton
cuda_graphs: enabled
model: Qwen/Qwen3-30B-A3B-Instruct-2507
```

## Environment

Use the normal vLLM/NIXL conda environment:

```bash
source /home/wxzheng/miniconda3/etc/profile.d/conda.sh
conda activate vllm-nvlink
cd /home/wxzheng/uccl/vllm-nvlink
```

The run expects the Qwen3 MoE model cache, NIXL, AIPerf, FlashInfer, and the local
P/D launcher to already be available in the environment.

## Re-run The Main Experiment

This command starts the P/D service, runs the 1000-request warmup, then runs the
2000-request main interval. CUDA graphs are enabled and model-internal Python
phase tracing is disabled, which is the intended production-like CPU/JSONL
profile mode.

```bash
RUN_NAME=e2e_agrs_nixl_cpu_2000req_r20_o1000_$(date -u +%Y-%m-%dT%H-%M-%SZ) \
ALL2ALL_BACKEND=allgather_reducescatter \
MOE_BACKEND=triton \
REQUEST_RATE=20 \
MAX_OUTPUT_TOKENS=1000 \
GPU_MEM_UTIL=0.85 \
VLLM_PD_TRACE_MODEL_PHASES=0 \
ENFORCE_EAGER=0 \
bash playground/e2e_agrs_nixl/e2e_2000req/run_cpu_profile.sh
```

The runner writes:

```text
playground/log/e2e_agrs_nixl/$RUN_NAME/pd_trace/
playground/out/aiperf_pd/e2e_agrs_nixl/$RUN_NAME/
```

## Analyze The Run

Generate `summary.md`, `summary.csv`, raw metric CSVs, and distribution plots:

```bash
python playground/e2e_agrs_nixl/e2e_2000req/analyze_cpu_profile.py \
  --run-name "$RUN_NAME"
```

The analyzer writes:

```text
playground/out/cpu_profile/e2e_agrs_nixl/$RUN_NAME/
```

## Notes

- `REQUEST_RATE` is the global Poisson arrival rate.
- `MAX_OUTPUT_TOKENS` is passed to AIPerf as OpenAI `max_completion_tokens`.
- The canonical analysis window is the `main_start` to `main_done` interval in
  `phase_markers.jsonl`; warmup is intentionally excluded from the summaries.
- Keep raw `pd_trace/*.jsonl` and `inputs.json` files out of GitHub if they exceed
  100 MB. Commit summaries and plots; archive raw payloads externally if needed.

## Attention/MoE/KV-Transfer Timeline Run

Use a short eager run with model phase tracing enabled. This is not intended as a
throughput benchmark; it is an explanatory trace for CPU-side attention, MLP,
MoE, and NIXL transfer overlap.

```bash
RUN_NAME=e2e_agrs_nixl_eager_decoder_layers_r2_o128_$(date -u +%Y-%m-%dT%H-%M-%SZ) \
ALL2ALL_BACKEND=allgather_reducescatter \
MOE_BACKEND=triton \
WARMUP_COUNT=5 \
MAIN_COUNT=20 \
REQUEST_RATE=2 \
MAX_OUTPUT_TOKENS=128 \
GPU_MEM_UTIL=0.75 \
VLLM_PD_TRACE_MODEL_PHASES=1 \
ENFORCE_EAGER=1 \
bash playground/e2e_agrs_nixl/e2e_2000req/run_cpu_profile.sh
```

Generate a compact overlap plot from the trace:

```bash
TRACE=playground/log/e2e_agrs_nixl/$RUN_NAME/pd_trace
OUT=playground/out/cpu_profile/e2e_agrs_nixl/$RUN_NAME/phase_timeline_overlap

python playground/e2e_agrs_nixl/find_overlap_window.py \
  --trace-dir "$TRACE" \
  --window-sec 0.12 \
  --compute-kinds attention,moe \
  --min-xfers 1 \
  --top 10

python playground/e2e_agrs_nixl/plot_phase_timeline.py \
  --trace-dir "$TRACE" \
  --out-dir "$OUT" \
  --style overlap \
  --window-start-sec 212.943 \
  --window-sec 0.12 \
  --include-kinds attention,mlp,moe,kv_transfer,kv_start_load,kv_finalize,kv_get_finished,forward \
  --overlap-forward-context \
  --overlap-idle-gap-ms 15 \
  --min-duration-ms 0.02 \
  --max-bars 10000
```

Validated timeline trace run:

```text
e2e_agrs_nixl_eager_decoder_layers_r2_o128_2026-06-03T03-10-04Z
```

The best overlap plot from that run is:

```text
playground/out/cpu_profile/e2e_agrs_nixl/e2e_agrs_nixl_eager_decoder_layers_r2_o128_2026-06-03T03-10-04Z/phase_timeline_overlap_212943/pd_phase_timeline.png
```

Timeline caveat: phase bars are CPU-side Python/eager envelopes, not synchronized
CUDA kernel timings. They are best used for explaining ordering and overlap, not
for reporting precise GPU kernel duration.
